# 미션 등급 도입과 절차 경량화 설계 리뷰

## 요약

작은 미션에서 worker 계층과 반복 문서를 줄이는 방향은 타당하지만, 현재 설계 그대로 구현하면 완료 검증을 우회하거나 등급 상향 뒤 불필요한 재작업이 발생할 수 있습니다. 완료 전이의 검증 위치, 등급 변경 시 산출물 처리, Codex의 세션 분리 규칙을 보완해야 합니다.

## 지적 사항

### [HIGH] S 필수 증거 검사가 실제 완료 경로에 연결되지 않음

- 위치: 설계의 “S 불변식 검사”, “완료 게이트” · `scripts/harness-company-complete.sh`, `scripts/harness-stop.sh`, `commands/{goal,submission,hot-fix}.md`
- 문제: 완료 스크립트는 worker evidence validator를 호출하지 않습니다. 또한 명령 문서는 먼저 미션을 `active:false`로 바꾸도록 지시하므로 `latest-active` 검사에서 완료 대상이 빠집니다. 완료 후에는 Stop 훅도 즉시 종료합니다. 따라서 validator에 S 필수 문서 검사를 추가해도 “두 문서가 있어야 complete 허용”이라는 보장은 성립하지 않습니다.
- 수정안: 완료 대상을 확정하고, 해당 미션의 필수 문서와 검증 결과를 검사한 뒤 terminal 상태로 전이하도록 설계하십시오. 명령 문서의 선행 `active:false` 지시도 함께 수정해야 합니다. 문서 누락·CQO FAIL 상태에서 완료 호출이 실패하고 기존 상태가 유지되는 통합 테스트를 추가하십시오.

### [HIGH] 등급 상향 시 기존 산출물을 새 요구에 맞추는 규칙이 없음

- 위치: 설계의 “분류가 틀렸다면”, “상향만 허용” · `scripts/harness-worker-evidence-validate.sh`
- 문제: S에서 CTO가 직접 구현한 뒤 M으로 올리면 기존 `cto.md`에 대응하는 worker 보고서가 없어 차단됩니다. M에서 L로 올리면 기존 축약 보고서 전부에 하위 섹션이 요구됩니다. “이미 쓴 문서는 유지”만으로는 이 충돌이 해결되지 않아, 과거 작업을 다시 시키거나 사후에 worker 증거를 만들어내게 됩니다. 반대로 하향은 경고만 남기므로 설계의 하향 금지도 강제되지 않습니다.
- 수정안: 상향 전에 끝낸 작업의 증거는 당시 등급 기준으로 보존하고, 추가 작업과 최종 검증에 적용할 요구를 명시하십시오. 현재 등급이 기록된 최고 등급보다 낮으면 차단하거나 최고 등급을 적용해야 합니다. S→M, S→L, M→L 및 하향 시도 테스트를 추가하십시오.

### [HIGH] 별도 검증 세션 불변식이 기존 Codex 어댑터와 충돌함

- 위치: 설계의 I1 및 S 직접 검증 · `assets/templates/AGENTS.md.template:29`, 각 Owner 명령의 Codex adapter
- 문제: 기존 Codex 계약은 별도 에이전트 없이 같은 세션에서 역할 스킬을 순차 실행하는 것을 허용합니다. 이 문구를 유지하면 CTO와 CQO 문서를 같은 세션에서 작성해도 기존 어댑터에는 부합하지만, 새 설계의 maker≠checker 조건은 위반합니다. CEO 확인만으로 해결할 수 있는 문제가 아니라 실행 지침 자체의 충돌입니다.
- 수정안: 실제 별도 검증 세션과 단순 역할 전환을 구분하고 어댑터에도 동일하게 반영하십시오. 별도 세션을 확보할 수 없을 때 사용할 독립 검증 경로와 완료 제한을 명시해야 합니다.

### [MEDIUM] M 경량화를 다시 무효화하는 하위 스킬 요구가 남음

- 위치: 설계의 변경 파일 목록 · `HR-Resource/resource-manager/SKILL.md:33`, `HR-Resource/hiring/SKILL.md:36`, `assets/templates/worker-report.md.template`
- 문제: resource-manager는 모든 worker에게 Implementation Notes의 네 하위 섹션을 요구하지만 변경 대상에서 빠져 있습니다. hiring도 Lessons Tally와 보고서 골격을 브리프에 그대로 복사하고 누락된 요청을 거절하도록 되어 있는데, 설계는 S 호출 금지만 추가합니다. M에서는 이 경로를 계속 사용하므로 축약 형식이 거부되거나 기존 문서 비용이 그대로 남습니다. 공용 템플릿을 L 전용이라고 표시하는 것만으로 M의 작성 경로가 정리되지 않습니다.
- 수정안: resource-manager와 hiring의 보고서 계약에도 S/M/L 적용 범위를 반영하십시오. M의 최소 보고서 형식과 seed 방법을 정하고, 실제 배정→브리프→보고서→validator 경로로 검증하십시오.

### [MEDIUM] L의 OPS 무조건 필수화가 기존 동작보다 절차를 늘림

- 위치: 설계의 OPS watch 정책과 등급별 흐름표 · `HR-Resource/cqo/SKILL.md:99`, `assets/templates/AGENTS.md.template:184`
- 문제: 현행 OPS watch는 실행 환경을 사용하는 검증에 적용됩니다. 설계의 “L 필수”는 외부 문서·스펙 검토처럼 감시할 런타임이 없는 미션에도 OPS를 요구합니다. tier가 없는 기존 미션도 L이므로 “기존 동작 유지”와 충돌하며, 경량화 요청과 반대로 불필요한 역할 호출을 늘립니다.
- 수정안: L에서도 감시 대상 런타임이 있는 경우에만 OPS watch를 요구하고, 없는 경우 근거를 기록해 N/A를 허용하십시오. tier 없는 비실행형 미션의 회귀 테스트를 포함하십시오.
