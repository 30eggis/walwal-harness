# 미션 등급·절차 경량화 2차 설계 리뷰

## 요약

완료 전 검증 연결, worker 보고서 형식 통일, OPS 조건 복원은 이전 지적을 반영했습니다. 별도 세션을 우선하고 불가 시 한계를 공개하는 반박도 수용합니다. 다만 새 판정 파서가 FAIL을 PASS로 오인할 수 있고, 취소 경로와 S의 OPS 실행 규칙에 충돌이 남아 있어 보완이 필요합니다.

## 지적 사항

### [HIGH] 설명문에 등장한 PASS가 실제 실패 판정을 뒤집을 수 있음

- 위치: 검증 규칙의 “판정 토큰” · `scripts/harness-company-complete.sh`
- 문제: CQO Verdict 본문에서 마지막 상태 토큰을 찾으면 `FAIL — 회귀 테스트를 수정한 뒤 PASS 가능`도 PASS로 처리됩니다. 반대로 `PASS — 이전 FAIL 원인 해결`은 거부됩니다. 설명문·인용·과거 판정을 모두 검색하는 방식으로는 현재 판정을 확정할 수 없습니다.
- 수정안: 판정 섹션 안에 `Verdict: PASS`처럼 전용 상태 줄을 정의하고, 유효한 전용 줄의 마지막 값만 읽으십시오. 설명문의 토큰은 판정에 사용하지 않고, 누락·잘못된 값은 거부해야 합니다. 위 두 사례와 판정 정정 사례를 테스트에 추가하십시오.

### [MEDIUM] 취소·종료 경로가 완료용 증거 검사에 막힘

- 위치: “cancelled/superseded 종료”, 완료 스크립트 변경 목록, 테스트 14 · `scripts/harness-company-complete.sh`
- 문제: 설계는 취소 시 **판정 검사만** 생략합니다. 그러면 S 미션을 CQO 착수 전에 취소해도 뒤의 필수 `Verification Commands`·`Verification Session` 검사에서 거부됩니다. M/L도 작성 중인 역할 문서에 worker 보고서가 없으면 validator에 막힙니다. `closed`는 명령 문서에서 지원하지만 면제 대상에는 없습니다. 이미 `active:false`를 기록한 뒤 거부되므로 문서와 runtime 상태도 어긋납니다.
- 수정안: 성공 완료와 산출물을 수락하지 않는 종료를 검사 시작 전에 분기하십시오. 취소·대체 종료에는 완료용 증거 검사를 요구하지 않고 해당 lifecycle을 보존해야 합니다. `closed`의 의미도 명시하고, S/M/L 각각에서 미완성 문서가 있는 취소·대체·종료 경로를 테스트하십시오.

### [MEDIUM] S에서 OPS watch는 필수인데 필요한 worker를 고용할 수 없음

- 위치: I7, 등급별 OPS 흐름, hiring 변경안 · `HR-Resource/ops/SKILL.md:23`, `HR-Resource/hiring/SKILL.md`
- 문제: 작은 UI 수정도 실행 환경에서 검증하면 S에 OPS watch가 필요합니다. OPS는 기존 규칙대로 worker를 통해 증거를 수집해야 하지만 새 hiring 규칙은 S에서 호출을 전면 금지합니다. 필요한 Ops worker가 없는 설치 환경에서는 정상적인 S 미션을 진행할 수 없습니다. validator의 S 전체 worker 면제도 직접 실행을 허용한 CTO/CQO보다 범위가 넓습니다.
- 수정안: S의 worker·hiring 생략을 CTO 직접 구현과 CQO 직접 검증에 한정하십시오. OPS가 필요한 경우 기존 worker 배정·고용과 증거 요구를 유지하고, Ops worker가 없는 S 런타임 검증 사례를 추가하십시오.

### [MEDIUM] 최고 등급 계산이 최초 높은 등급을 놓침

- 위치: “유효 등급” 및 검증 규칙의 `max(tier, tier_history[].to)`
- 문제: 처음 L로 시작한 미션이 `tier:"S"`, `tier_history:[{from:"L",to:"S"}]`로 기록되면 계산 대상에는 S만 남습니다. 따라서 “하향 기록은 효력이 없다”는 보장이 깨집니다. 현재 테스트는 앞선 S→L 기록이 있는 경우만 확인합니다. 또한 jq 문자열 `max`를 그대로 사용하면 문자 순서가 등급 순서와 다릅니다.
- 수정안: `S=0, M=1, L=2`처럼 순위를 명시하고 현재 값과 이력의 `from`·`to` 모두에서 최고 등급을 구하십시오. 최초 L→S, M→S 및 잘못된 이력 값 테스트를 추가하십시오.

### [MEDIUM] 상향 전 작업 면제가 상향 후 추가 구현까지 덮음

- 위치: “S→M/L 산출물 처리”, validator의 `Direct Work` 면제
- 문제: `from:"S"` 이력과 `## Direct Work`만 있으면 역할 전체의 worker 요구를 계속 면제합니다. 같은 `cto.md`에 상향 후 구현이 추가되어도 worker 없이 통과하므로 “과거 작업만 보존하고 이후 작업은 worker로 수행”한다는 규칙을 검증하지 못합니다.
- 수정안: 면제를 CTO의 상향 전 완료 범위로 한정하고 그 범위를 기록하십시오. 상향 후 추가 구현이 있으면 대응 worker 보고서를 요구해야 합니다. 추가 구현 없이 재검증만 하는 경우와, 추가 구현이 있지만 worker 증거가 없는 경우를 구분해 테스트하십시오.
