# 검증 증거 재사용·산출물 위생 설계 2차 리뷰

## 요약

상위 지침과의 충돌 해소, 필요한 재검증과 예방 가능한 재작업의 구분, 실패 판정 규칙 보강은 이전 지적을 반영했습니다. 다만 지문이 제외하는 실행 환경의 동일성, 기준 실행과 지문의 연결 시점이 아직 불명확하며, 새 누출 검사 예시는 비밀을 다시 노출하므로 수정이 필요합니다.

## 지적 사항

### [HIGH] 누출 검사 예시가 비밀을 명령 인자와 출력에 노출합니다

- 위치: 「Verification Artifact Hygiene → 비밀정보」의 `grep -rF -- "$VAR"` 예시.
- 문제: 셸은 `$VAR`를 실제 값으로 확장해 grep의 명령 인자로 전달합니다. 또한 grep은 기본적으로 일치한 줄 전체를 출력하므로, 누출을 발견하면 비밀이 도구 출력에 다시 기록됩니다. 더미 문자열로 실행해도 일치한 원문이 stdout에 출력되는 것을 확인했습니다. “명령줄·도구 출력에 비밀 금지”라는 같은 절의 규칙과 충돌합니다.
- 수정안: 검사 프로세스가 환경변수를 직접 읽고 파일 내용과 내부에서 비교하도록 하십시오. 출력은 발견 여부나 건수만 허용하고, 검색값과 일치한 원문은 출력하지 않아야 합니다. 더미 비밀을 넣은 검사에서 탐지는 성공하되 stdout·stderr에 더미 값이 없는지 확인하십시오.

### [HIGH] 소스 지문과 실행 대상 식별자가 같아도 실행 조건은 달라질 수 있습니다

- 위치: 「지문 경계」「E2E·실기기 증거」「Evidence Reuse」.
- 문제: `.env`, 설치된 의존성, 생성된 빌드 등은 지문에서 제외됩니다. `target`의 호스트·장치·계정·빌드 식별자가 같아도 환경변수, 장치 설정, 테스트 데이터나 세션 상태는 달라질 수 있습니다. 따라서 `target` 비교가 `.env` 변경을 보완한다는 설명은 성립하지 않습니다. 전체 테스트 역시 실행 명령·옵션과 환경 동일성을 재사용 조건으로 명시하지 않아, 같은 소스의 다른 실행 결과를 대신 사용할 수 있습니다.
- 수정안: 소스 지문은 재사용의 필요조건으로 한정하십시오. 검증 항목별로 명령·옵션과 관련 실행 환경이 동일함을 확인하고, E2E는 필요한 데이터·설정·세션 전제까지 확인해야 합니다. 제외된 입력의 동일성을 확인할 수 없으면 해당 검사만 재실행하도록 명시하십시오. 모든 환경을 해시하는 새 시스템까지 만들 필요는 없습니다.

### [MEDIUM] 기준 실행 도중 변경된 트리에 이전 결과를 연결할 수 있습니다

- 위치: 「Evidence Reuse」의 `Baseline` 기록 절차 및 신규 지문 스크립트 사용 방식.
- 문제: 지문을 테스트 전후 어느 시점에 계산하는지 정의하지 않았습니다. 테스트가 파일 A를 읽은 뒤 다른 세션이 A를 수정하고, 종료 후 지문만 기록하면 이전 코드의 PASS가 수정된 코드의 지문에 연결됩니다. 이후 비교는 일치하므로 설계의 “병행 세션 변경은 지문 불일치로 잡힌다”는 보장이 깨집니다.
- 수정안: 기준 실행 직전·직후 지문을 비교하고, 실행 중 관련 입력이 변경되었거나 변경 가능성을 배제할 수 없으면 재사용 가능한 baseline으로 인정하지 마십시오. 병행 편집이 있는 작업은 고정된 checkout에서 검증하는 방식도 가능합니다. 테스트 도중 입력이 바뀐 결과를 baseline으로 채택하지 않는 사례를 검증 계획에 추가하십시오.
