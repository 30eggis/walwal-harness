# 검증 증거 재사용·산출물 위생 설계 3차 리뷰

## 요약

이전 세 지적은 설계에 반영되었습니다. 환경 동일성을 별도로 확인하고, 실행 전후 지문 비교와 병행 편집 제한을 함께 적용하는 방식은 타당하며 고정 checkout을 의무화할 필요도 없습니다. 다만 새 누출 검사기의 검사 오류 처리와 과거 기록 대조 기준은 보완해야 합니다.

## 지적 사항

### [MEDIUM] 누출 검사 실패와 정상적인 미탐지를 구분해야 합니다

- 위치: 신규 `scripts/harness-secret-scan.sh`의 grep 결과 처리 및 테스트 계획.
- 문제: 설계는 “발견하면 exit 1, 발견하지 못하면 exit 0”만 정의합니다. grep은 정상 미탐지에 1, 읽기 오류 등에 2를 반환합니다. 입력 디렉터리가 존재해도 내부 파일을 읽지 못하거나 검사 중 파일이 사라질 수 있으므로, 사전 경로 검사만으로는 충분하지 않습니다. 이를 미탐지로 처리하면 불완전한 검사에 `leaks=0`을 발행하게 됩니다.
- 수정안: grep의 종료 코드 0은 누출 발견으로 매핑하고, **1일 때만** `leaks=0`과 exit 0을 반환하십시오. 2 이상은 검사 실패로 exit 2를 반환하고 정상 미탐지 문구를 출력하지 않아야 합니다. 검사 도중 읽기 오류가 발생하는 사례를 회귀 검사에 추가하십시오.

### [LOW] 과거 사례 대조의 예상 결과가 새 재사용 조건과 맞지 않습니다

- 위치: 「테스트 계획 → 기록 대조」의 “ACFEFW-62 work-3·4에서는 전체 테스트를 재사용한다”.
- 문제: 당시 기록에는 새 `run` 모드가 생성한 baseline이 없고, 전체 커버리지 명령은 기존 범위 밖 문제로 실패했습니다. 새 설계는 수기로 만든 baseline과 `exit≠0`인 실행의 재사용을 금지하므로, 당시 기록을 그대로 넣어 재사용 성공을 기대할 수 없습니다.
- 수정안: 역사적 기록 대조와 새 규칙의 가상 적용을 구분하십시오. 실제 기록은 baseline 부재로 재사용 불가이며, 가상 적용은 유효한 baseline과 exit 0을 전제로 명시해야 합니다. 기존 실패 결과를 성공으로 바꾸거나 재사용 조건을 완화할 필요는 없습니다.
