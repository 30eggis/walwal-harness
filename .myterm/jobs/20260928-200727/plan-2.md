# 테스트 과다 실행의 근본 원인 재분석과 검증 증거 재사용·산출물 위생 설계 (합의 2차)

## 요약
ViOnyx-WebFront의 MyTerminal 기록 11건을 다시 측정했습니다. 각 단계의 `*.started`와 `*.result.json` mtime을 비교했고, trace에서는 도구 호출 간격과 Agent 호출 수를 셌습니다.

측정 결과, 테스트 명령 자체가 1~2시간을 차지한 작업은 "시나리오 등록과 실행" 요청 하나뿐입니다. 이 작업에서는 테스트가 곧 산출물이었습니다. 나머지 작업의 1~2시간은 다음 세 가지에서 나왔습니다.
- **리뷰 반려 → 재작업 라운드의 반복.** 반려 사유는 주로 제품 코드가 아니라 검증 스크립트 결함과 하네스 기록이었습니다.
- **라운드마다 4~7개 Agent 세션을 띄우는 L 절차.** 대상 프로젝트에 설치된 하네스가 tier 도입 이전 버전이라 모든 미션이 L로 처리됐습니다.
- **승인 대기 같은 유휴 시간.**

이 설계는 세 가지를 합니다.
- 일회용 검증 스크립트가 처음부터 누출 없이, 실패하면 실패로 끝나게 만드는 규칙을 스킬에 넣습니다. 반려 라운드의 주원인을 없애기 위해서입니다.
- 현재 규칙은 "모든 tier에서 미션마다 전체 테스트 실행"을 요구합니다. 여기에 **작업 트리 지문(fingerprint)이 같을 때만 허용하는 증거 재사용** 규칙을 추가합니다. 새 tier 체계에서 hot-fix마다 전체 테스트를 다시 돌리는 일을 막기 위해서입니다.
- 이 재사용 규칙이 상위 지침과 모순되지 않게, 설치되는 지침 문구도 함께 고칩니다.

- **근본 원인 R1 — 설치본이 tier 이전 버전이라 모든 미션이 L 절차로 돈다.**

  - 그래서 한 줄짜리 수정이나 검증 스크립트 보정에도 라운드마다 CTO·워커·CQO·evaluator를 포함한 Agent 4~7개가 새 세션으로 뜹니다(ACFEFW-62에서 7/6/4개, AICP-56에서 4/4/4개). 각 세션은 lessons를 읽고 역할 문서를 씁니다.
  - 해결책은 이미 현재 워킹트리의 미커밋 tier 작업(`commands/*.md`, `HR-Resource/ceo|cqo|cto`, `tests/mission-tiers.sh`)에 들어 있습니다. 이번 설계는 그 작업을 중복하지 않습니다.
  - 남은 조치는 릴리스한 뒤 대상 프로젝트에서 `walwal-harness init`를 다시 실행하는 것입니다.

## 모호점과 해소안
- **증거 재사용의 동일성 판단** → 파일 목록 해시를 LLM에게 맡기지 않고, 작업 트리 전체 지문을 계산하는 스크립트를 새로 만듭니다. 해시 대상 목록을 사람이나 LLM이 고르면 lockfile, 설정, 파일 추가·삭제가 빠집니다(리뷰 HIGH).
  - 지문 입력은 `HEAD` 커밋, `.harness/`·`.myterm/`을 뺀 `git diff HEAD --binary`, 무시되지 않은 비추적 파일의 경로와 내용 해시입니다.
  - gitignore된 경로(`test-results/`, `node_modules/`)는 제외됩니다. 검증 산출물을 gitignore 경로에 두게 하는 위생 규칙과 맞물립니다.
  - 다른 세션이 제품 파일을 바꾸면 지문이 달라져 재사용이 불가능해집니다. 보수적이지만 의도한 동작입니다.
- **E2E·실기기 증거** → 소스 지문만으로는 재사용하지 않습니다. 다음이 모두 같을 때만 재사용합니다.
  - 지문
  - 검증 스크립트 자체의 sha256(gitignore 경로라 지문에 포함되지 않음)
  - 실행 대상(호스트·장치·계정·빌드 식별자)
  - 합격 기준
  - 하나라도 다르거나, 검증 로직의 결함이 발견됐거나, 새 요구가 생기면 그 항목만 다시 실행합니다.
- **실행 횟수 정의** → "미션당 마지막 1회" 같은 절대 상한은 두지 않습니다(리뷰 반영). 기준은 다음과 같습니다.
  - 전체 테스트 증거는 최종 지문에 대해 유효하면 됩니다.
  - 지문이 바뀌지 않은 라운드에서는 다시 돌리지 않습니다.
  - 제품 변경이나 실패 원인 수정으로 지문이 바뀌면 다시 돌립니다.
  - 범위 내 테스트는 그 범위가 바뀌었을 때 다시 돌립니다.
- **템플릿 수정 여부** → 수정합니다. 루트 `AGENTS.md`의 승인 규칙은 이 저장소 자체의 `AGENTS.md`에 대한 것이고, 템플릿은 설치물 소스입니다. 문구 충돌을 남기면 실행 담당자가 서로 모순된 지시를 받습니다. 괄호 한 구절만 덧붙입니다.
- **완료 게이트 스크립트** → 수정하지 않습니다. `harness-company-complete.sh`는 S에서 `## Verification Commands` 제목과 `Verification Session` 줄만 검사하므로, `Reused:` 줄은 그 섹션 안에서 그대로 통과합니다.
- **hot-fix 1단계의 goal tier 기록(1차 설계 항목)** → 뺍니다. hot-fix 미션 자체의 tier는 이미 4단계가 기록합니다. ViOnyx의 R1은 이 경로가 아니라 구버전 설치 때문입니다(YAGNI).
- **리뷰어가 하네스 기록까지 검토해 라운드가 늘어나는 문제(AICP-56)** → MyTerminal 앱 쪽 문제라 이 저장소에서는 바꾸지 않습니다. 결과 보고에 권고로 남깁니다.
  - 리뷰 범위는 제품 diff와 요청 산출물로 한정합니다.
  - 하네스 기록만 지적된 경우 LLM 트랙으로 처리합니다.
- **ACFEFW-62 hot-fix-1(자격 증명 노출)의 tier** → 새 체계에서도 보안 기준에 걸려 L이 될 수 있습니다. 보안 분류 완화는 Owner 판단 사항이라 바꾸지 않습니다.

## 변경 파일
- `scripts/harness-verify-fingerprint.sh` (신규, 약 20줄) — `harness-verify-fingerprint.sh <project-root>`
  - git 저장소가 아니거나 git이 실패하면 stderr에 이유를 쓰고 exit 2로 끝납니다. 이 경우 재사용할 수 없습니다.
  - 정상이면 앞의 지문 입력을 `shasum -a 256`(없으면 `sha256sum`)으로 해시해 한 줄로 출력합니다. 해시 도구 선택 방식은 `harness-spec-pin.sh`의 `hash_of`를 따릅니다.
  - `init`이 `scripts/`를 통째로 복사하므로 설치 절차 변경은 필요 없습니다.
- `HR-Resource/cqo/SKILL.md`
  - `:31`(Tier S) — "execute changed-scope tests and the available full suite directly" 뒤에 "(or cite a still-valid run under Evidence Reuse below)"를 붙입니다.
  - "Test Coverage Scope And Full Gate"의 2번 "once, near the end" 문구를 바꿉니다. 새 문구는 "최종 지문에 유효한 1회. 지문이 바뀌면 갱신하고, 지문이 같은 라운드에서는 반복하지 않음"입니다.
  - 같은 절에 **Evidence Reuse** 문단을 추가합니다.
    1. 전체 테스트나 E2E를 실행할 때마다 `## Verification Commands`에 `Baseline:` 줄을 기록합니다. 내용은 명령, 로그 경로, exit code, `fingerprint=<스크립트 출력>`, 합격 기준 참조입니다. E2E라면 `script_sha256=`과 `target=`도 넣습니다.
    2. 이후 라운드나 같은 goal 아래의 hot-fix·submission에서는 새로 실행한 지문 스크립트의 출력과 exit 0을 적고, `Reused: <baseline 문서#항목>`으로 재실행을 대신할 수 있습니다.
    3. 조건 하나라도 확인할 수 없거나 불일치하면 그 항목만 다시 실행합니다.
    4. 검증 로직의 결함이 발견되면 그 로직에 의존한 증거는 모두 무효입니다.
    5. M/L에서는 evaluator 워커가 재사용 여부를 판단하고, CQO는 그 보고를 인용합니다.
  - **Verification Artifact Hygiene** 섹션을 신설합니다.
    - **기존 도구 우선:** 새 스크립트보다 프로젝트의 러너(시나리오 러너, vitest, playwright 설정)를 먼저 씁니다.
    - **비밀정보:** 자격 증명은 환경변수로만 받습니다. 없으면 브라우저를 열기 전에 non-zero로 종료합니다. 비밀을 명령줄, 로그, 도구 출력, 임시 파일에 출력하지 않습니다. 누출 검사는 `grep -rF -- "$VAR"`처럼 환경변수로 하고, 패턴 파일에 비밀을 쓰지 않습니다.
    - **정제:** URL은 경로만 기록합니다(쿼리 제거). 인증 헤더, 쿠키, 티켓, 요청·응답 원문은 기록하지 않고 키 목록, 개수, 식별자만 남깁니다. 결과 파일 저장 직전에 금지 패턴을 검사해 발견되면 실패로 끝냅니다.
    - **캡처:** 검증 대상 요소 단위로 찍거나 마스킹합니다. 개인정보나 얼굴이 담긴 전체 화면 캡처는 금지합니다.
    - **fail-closed:** 필수 단계를 조건문(`if`) 뒤에 두지 않고 assert합니다. 기대 요청 건수는 정확히 assert합니다(빈 배열 `every()` 금지). 양성·음성 대조군을 모두 assert합니다. 예외가 나면 non-zero로 끝납니다. `pass=true`는 모든 assert를 통과한 마지막에만 설정합니다.
    - **fail-closed 입증:** 다음 네 경로가 각각 non-zero로 끝나는지 기록합니다: 자격 증명 누락, 필수 대상 없음 또는 요청 0건, 대조군 실패, 예외. 가능한 경로는 한 assert를 강제로 거짓으로 만든 사본을 실행해 확인합니다.
    - **보관:** 산출물은 gitignore 경로에 둡니다. `Baseline`이 참조하는 정제된 최종 증거는 보존합니다. 정제 전 중간 산출물은 판정 후 삭제하고, 삭제 권한이 없으면 기존 block 규칙을 따릅니다.
- `HR-Resource/cto/SKILL.md` — "Test Coverage Scope"에 한 줄을 추가합니다. 내용은 "검증 스크립트를 쓰거나 워커에게 맡길 때 CQO의 Verification Artifact Hygiene을 따르고, 그 절을 워커 브리프에 그대로 옮긴다"입니다.
- `assets/templates/AGENTS.md.template:109` — "run changed-scope tests and the available full suite" 뒤에 " (a prior run is reusable only under CQO Evidence Reuse)"를 붙입니다.
- `assets/templates/AGENTS-ko.md.template:95` — 같은 위치에 "(이전 실행은 CQO 증거 재사용 조건을 충족할 때만 재사용)"을 붙입니다.

## 검증 규칙
- **지문 스크립트 입력 검증**
  - 인자가 없으면 `.`을 씁니다.
  - 경로가 없거나 git 저장소가 아니면 exit 2로 끝나고 아무것도 출력하지 않습니다.
  - 해시 도구가 없으면 exit 2로 끝납니다(`NOHASHER` 같은 가짜 값을 출력하지 않음).
  - 출력은 64자리 16진수 한 줄뿐입니다.
- **재사용은 실패 쪽이 기본값입니다.** 지문 exit가 0이 아닌 경우, 로그 파일이 없는 경우, baseline exit code가 없는 경우, 합격 기준이 바뀐 경우에는 모두 재실행합니다.
- **E2E 경계.** `script_sha256`과 `target` 중 하나라도 다르면 재실행합니다. 리뷰나 CQO가 검증 로직의 결함(fail-open, 대조군 미검증 등)을 지적하면, 그 스크립트에 의존한 이전 PASS는 무효입니다.
- **지문 경계.**
  - `.harness/`·`.myterm/` 문서, gitignore 산출물 변경 → 지문 유지(재사용 가능).
  - 추적 파일 수정, 삭제, 추가, lockfile·설정 변경, 무시되지 않은 비추적 파일 추가 → 지문 변경(재실행).
  - gitignore된 `.env` 같은 실행 환경 변경은 지문이 잡지 못합니다. 그래서 E2E는 `target` 비교를 따로 요구합니다.
- **문서만 바뀐 라운드.** 런타임을 띄우지 않았으면 `OPS N/A: docs-only`로 기록합니다(기존 규칙).
- **tier.** 재사용 규칙은 S/M/L 공통입니다. tier 기본값(`unknown → L`)은 바꾸지 않습니다.

## 리뷰 반영
- **[반영] 일부 파일의 해시 일치만으로 전체 테스트·E2E 증거를 재사용할 수 없음 (HIGH)**
  - LLM이 고르는 "handoff 변경 파일 + 테스트 해시"를 버렸습니다.
  - 대신 `harness-verify-fingerprint.sh`가 작업 트리 전체의 지문을 계산합니다. `HEAD`, `git diff HEAD --binary`, 비추적 파일을 포함하므로 추가, 삭제, lockfile, 설정 변경을 모두 잡습니다.
  - E2E는 지문에 더해 `script_sha256`, `target`, 합격 기준까지 일치해야 재사용합니다.
  - 검증 로직의 결함이나 새 요구가 나오면 해당 증거를 무효화하고 그 항목만 다시 실행하는 규칙을 Evidence Reuse에 넣었습니다.
  - 기록에 있던 병행 세션의 제품 변경은 지문 불일치로 이어져 재실행됩니다.
