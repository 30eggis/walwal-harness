# MyTerminal 이슈 전달 문서 6차 설계리뷰

## 요약

메모리에 중단 대상을 보존하고 재중단 시 우선 사용하는 변경으로 이전 첫 번째 지적은 해소됐습니다. 결과 검증 강화도 디렉터리·깨진 JSON 문제를 해결하지만, 새로 선택한 디코딩 방식이 기존 결과 형식과 호환되지 않아 한 가지 회귀가 남습니다.

## 지적 사항

### [MEDIUM] 정상적인 구형 결과를 읽기 실패로 판단해 중단 차단이 해제되지 않음

- 위치: `recordFailure`의 `JobJSON.decode(StepResult.self, from:)` 조건 · [Job.swift](/Users/ted/project/myterminal/Sources/MyTerminal/Pipeline/Job.swift:360)
- 문제: 기존 `StepResult.load`는 `agent`·`version`이 없는 구형 결과를 `Legacy`로 읽어 변환합니다. 반면 `StepResult` 직접 디코딩에는 필수 필드인 `agent`가 필요합니다. 따라서 구형 결과가 있는 단계의 중단을 마무리하면 정상 결과도 읽기 실패로 판단하고 `confirmed` 기록과 차단을 계속 유지합니다. 설계에 포함된 구형 계획 마이그레이션과 기존 결과 보존 정책에 맞지 않습니다.
- 수정안: 기존 로더의 신·구 형식 판별과 변환을 재사용하면서, 실제 디코딩 실패를 구분하는 검증 경로를 마련합니다. `StepResult.load != nil`만 확인하는 방식도 피해야 합니다. 이 함수는 깨진 JSON에도 표시용 실패 결과를 반환하기 때문입니다. 정상 신형·정상 구형은 원문을 보존하며 마무리에 성공하고, 디렉터리·깨진 JSON은 차단을 유지하는 테스트를 추가합니다.
